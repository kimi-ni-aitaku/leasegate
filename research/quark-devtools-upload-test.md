# Chrome DevTools MCP：真实二维码上传与手机扫码联调

2026-10-11，使用用户已安装的 Chrome DevTools MCP 1.10.1，在独立 Chrome 配置目录中打开夸克官网。原账号浏览器保持登录；用户自行在手机上扫码并确认。本次确认了实际浏览器登录和真实截图识别，没有把会员 Cookie 注入测试浏览器。

| 环节 | 实测结果 |
| --- | --- |
| 官方生成二维码 | `getTokenForQrcodeLogin` HTTP 200，业务状态 `2000000` |
| 确认前轮询 | `getServiceTicketByQrcodeToken` 业务状态 `50004001` |
| 登录票据兑换 | 实际 `pan.quark.cn/account/info?st=…&lw=…` HTTP 200；存在非空票据及 `Set-Cookie` |
| 登录后账号检查 | `account/info?fr=pc&platform=pc` 返回 `success=true`、`code=OK` |
| 会员检查 | 官方会员接口返回状态 200、`code=0`、`member_type=SUPER_VIP` |
| 浏览器页面 | 进入 `pan.quark.cn/list`，不再显示扫码登录页 |

导航前的成功轮询和票据兑换响应体在 MCP 中已不可读取，因此没有推测它们的业务状态。证据来自保留的请求 URL、响应头，以及登录后的账号、会员响应和页面状态。文件列表响应正文被工具截断，只记录其状态 200、`code=0`，不导出文件名或内容。

## 修复

- VIP 截图上传、拖拽、粘贴采用统一服务器解码，按文件实际签名确定 MIME，不依赖文件扩展名或浏览器 MIME。
- 服务器处理透明背景及 EXIF 方向，识别全部二维码。`purpose=quark_web` 筛选来源和参数均正确的夸克电脑网页登录码；普通下载二维码不会被误选；多个不同登录码时要求裁剪。
- 识别完成后再提交授权。未配置真实授权端时，只显示“二维码已识别，尚未登录”，不扣次数、不建立任务或启动计时；错误提示保留到下一次输入。
- 识别过程中拒绝重复输入，卡密切换后不提交此前仍在解码的截图。
- 修正旧凭据轮换测试对随机账号分配顺序的假设，核对实际被占用的账号。

新增六个图片回归用例，完整测试为 **97 passed，3 skipped**。买家页面已实际验证无 MIME 文件上传、登录码与下载码混合截图、多个登录码拒绝和错误后重试。

## 实际边界

这次是用户手机确认后的官方浏览器登录。电脑抓包未捕获手机端 `loginWithKpsAndQrcodeToken` 请求及原生签名，不能据此宣称服务器凭 Cookie 自动确认已经完成。仍未接通真实 VIP 自动授权端和指定设备远程注销。

原始网络记录仅加密保存在私有工作目录；此报告及配套 JSON 只保存接口、字段名称和状态，不含 Cookie、token、Service Ticket、账号身份、原生签名或文件信息。
